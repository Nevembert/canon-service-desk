Canon Service Desk 0.2.0 — проверка, 2026-09-09

ЛОКАЛЬНО ПРОВЕРЕНО
- Сборка C# 5, AnyCPU, Mono mcs, предупреждения как ошибки.
- 22 теста базовой диагностики.
- 32 теста обслуживания: показания и их источник, переполнение/конфликты,
  история по устройствам, сохранение Total при локальной отметке, BJL-пакеты
  и ограничение допустимых команд, отпечаток задания и ABI Windows.

WINDOWS CI
Workflow собирает Microsoft .NET Framework EXE, запускает C#/Python/JS
тесты, проверяет управление изолированной очередью Windows (без физического
принтера), упаковывает приложение и запускает EXE из ZIP для снимков
всех вкладок и мастера абсорбера. Успех конкретного запуска проверяйте:
https://github.com/Nevembert/canon-service-desk/actions
Коммит сборки указывается в BUILD.txt внутри Windows ZIP.

НЕ ПРОВЕРЕНО НА ОБОРУДОВАНИИ
- Команды BJL, реальный USB и печать Canon G2411.
- Реальное внедрение Frida в Service Tool.
- Все варианты масштабирования Windows и все версии драйверов.

СБРОСЫ
Автоматического USB-сброса абсорбера/Total нет. Мастер абсорбера основан
на сообщении владельца G2411. Отметка после обслуживания хранится в приложении;
она не записывается в EEPROM и не подменяет аппаратные показания нулём.

ВОСПРОИЗВЕДЕНИЕ
Windows: build.cmd, tests/run_tests.cmd.
Python: python -m unittest discover -s tests -p "test_*.py" -v
JavaScript: node tests/test_observer.js
Сценарий .github/scripts/queue-integration.ps1 предназначен для временного
Windows CI runner: создаёт и удаляет только очередь Canon Service Desk CI.
