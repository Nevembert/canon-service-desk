ЗАПИСЬ ОБМЕНА SERVICE TOOL

Это отдельный дополнительный инструмент для выяснения причин 005/006.
Основное приложение CanonServiceDesk.exe не требует Python или Frida.

1. Для записи нужен Python 3.10+ для Windows с python.org, с Python Launcher (py).
2. Один раз запустите setup_trace.cmd. Он создаст окружение .venv в этой папке
   и скачает бесплатную библиотеку Frida из PyPI. Дождитесь Ready.
3. Закройте Service Tool, PrintHelp и окно состояния принтера.
   Оставьте Canon в том сервисном режиме, который PrintHelp уже распознавал.
4. Запустите start_trace.cmd и выберите ваш ServiceTool_v5103.exe.
   Наблюдатель сам запустит выбранный файл.
5. Дождитесь появления обычной ошибки при запуске. Если её нет, выполните
   только чтение EEPROM Save, которое раньше давало ошибку.
6. Закройте окно Service Tool. Наблюдатель сохранит JSONL, объяснение и ZIP.
   Путь к ZIP будет в консоли: обычно
   %LOCALAPPDATA%\CanonServiceDesk\Traces\дата_время.zip
7. Пришлите этот ZIP вместе с отчётом основного приложения и номером ошибки.

Наблюдатель не меняет EXE на диске, команды, ответы или проверки лицензии.
Он не генерирует команд принтеру. Кнопки Service Tool выполняют её обычные
операции: не запускайте очистку, сброс или изменение региона ради записи лога.
При Ctrl+C захват прекращается, уже запущенная Service Tool продолжает работу.

Записываются только открытые выбранным процессом пути Canon / VID_04A9:
CreateFile, DeviceIoControl, ReadFile, WriteFile, GetOverlappedResult/Ex и CloseHandle.
Асинхронный вывод читается после наблюдавшегося завершения. Способ IOCP,
WinUSB и работа через другие процессы пока не поддерживаются. Если данных
нет, это не доказательство отсутствия принтера. Захват может влиять на тайминги.
Вход и выход ограничены 4096 байтами на событие; усечение отмечается в JSON.

Важное различие: Win32 6 = недействительный дескриптор, а 006 Service Tool
относится к её собственному протоколу. Анализатор не смешивает эти коды.

Логи содержат только локальные данные, но могут включать серийный номер,
путь USB и байты обмена. Автоматической отправки и публикации нет.
Сначала просмотрите файлы перед публичной публикацией.

Исходники открыты и находятся рядом. Для повторного анализа без принтера:
  py -3 capture.py --analyze путь\к\usb-trace.jsonl

Если Frida не запускается: сохраните текст ошибки. Не отключайте защиту Windows
для обхода блокировки. Основное приложение может собрать отчёт без Frida.
