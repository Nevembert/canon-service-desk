# Поддержка обслуживания в 0.2.0

| Операция | Реализация | Подтверждение результата |
| --- | --- | --- |
| Абсорбер P07 / 5B00, G2411 | Пошаговый мастер: после входа в сервисный режим Stop ×5, Power ×1 | Запись наблюдения владельца после обычного включения и теста |
| Обнуление аппаратного Total / TPAGE | Не реализовано: подтверждённая команда G2411 не найдена | Кнопка/инструкция не выдаёт фиктивный успех |
| Страницы после обслуживания | Локальная отметка от введённого Total | Разница двух показаний из отчётов пользователя; EEPROM не меняется |
| Учёт остатка чернил после заправки | Инструкция сброса через Canon IJ Printer Assistant Tool | Пользователь проверяет результат в Canon IJ |
| Тест дюз, обычная/глубокая очистка, выравнивание, ролики, поддон, Ink Flush | Процедуры панели и Canon IJ | Шаги и результат записываются в историю |
| BJL: тест дюз / обычная очистка всех цветов / чёрного | Прямая запись в USBPRINT; опытный режим | Число записанных байтов + Win32; выполнение принтером не подтверждается |
| Задания Windows | Просмотр, пауза, продолжение, удаление одного выбранного задания | Повторное чтение очереди Windows |

## Сброс абсорбера

Последовательность Stop ×5 → Power ×1 сообщена владельцем **G2411**, уже обслужившим абсорбер. Она начинается **после входа в сервисный режим**. Мастер не переводит принтер в этот режим по USB. Для другой модели эти кнопки не подтверждены. Обслуженный абсорбер должен стоять на месте.

USB-сброс G2411 и аппаратное обнуление общего пробега пока не реализованы. Найденный открытый проект [canon-megatank-reset](https://github.com/Jesssullivan/canon-megatank-reset) описывает шифрованный протокол с живым ключевым словом и сообщает об аппаратной проверке на **G6020**. Это не доказательство совместимости с G2411. Команды этого профиля в наше приложение не перенесены.

Для добавления USB-сброса нужны идентификатор/прошивка конкретной модели, запись успешного обмена и результаты до/после. Встроенный наблюдатель `trace` помогает получить обмен. Его сырые записи нельзя автоматически воспроизводить: ключ сеанса может меняться. Ни платная Service Tool, ни её модифицированный EXE в проект не включены.

## BJL: границы реализации

Формат трёх команд изучен по открытому [commandtocanon.c из Gutenprint](https://github.com/echiu64/gutenprint/blob/master/src/cups/commandtocanon.c). В приложение включена самостоятельная реализация формирования этих пакетов и транспорта Windows.

Опытный режим требует `MFG:Canon` и отдельного токена `BJL` в поле `CMD` строки IEEE 1284. Отсутствие этого токена блокирует запись. Пользователь выбирает конкретный USB-интерфейс и подтверждает обычный режим/подготовку. Перед записью приложение эксклюзивно открывает тот же USBPRINT-путь и повторно сверяет полный идентификатор. Автоматических повторов записи нет. При ошибке или таймауте проверьте принтер и журнал до новой попытки.

Объявленная поддержка языка BJL не гарантирует поддержку каждой команды. На физическом G2411 эти отправки разработчиком не проверены. Очистка расходует чернила, а тест дюз — лист бумаги. Команд глубокого сброса, EEPROM, прошивки или региона в BJL-разделе нет.

## Показания и история

Вставляйте один текстовый отчёт: `Total 7522 Pages`, `Print 7469 Pages`, `Blank 53 Pages`, либо `TPAGE=7522`. Отсутствующие поля остаются неизвестными. Конфликтующие показания, переполнение и несовпадение Total с Print + Blank отклоняются. Фото, PDF и двоичный EEPROM этот импорт не разбирает.

Уменьшение Total отмечается для проверки, но не считается доказательством сброса. «Начать отсчёт после обслуживания» добавляет локальную отметку и сохраняет исходный Total. Подмена общего пробега нулём не производится.

История хранится по введённому имени/серийному номеру в `%LOCALAPPDATA%\CanonServiceDesk\History`. У разных устройств используйте разные имена. Повторная диагностика не удаляет историю. В экспортируемый ZIP попадает история выбранного устройства, а не всех устройств.
